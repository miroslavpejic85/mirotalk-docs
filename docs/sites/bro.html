Dual Architecture

Choose the Right Delivery Mode

Start lightweight with P2P, then use SFU forwarding when audience size or broadcaster bandwidth calls for it.

P2P Broadcasting

The broadcaster sends a stream to each viewer. Best for smaller audiences; broadcaster upload grows with each viewer, and TURN relays when direct connectivity is unavailable.

SFU Broadcasting

The broadcaster sends one upstream feed to the SFU, which forwards media to viewers. Capacity depends on server resources, throughput, quality, and deployment design.

Common Questions

MiroTalk BRO FAQ

Which broadcast mode should I use?
Use P2P for smaller audiences and lightweight deployments. Use SFU when one broadcaster upload needs server-assisted distribution to a larger audience.
How many viewers can it support?
There is no universal number. P2P depends mainly on broadcaster upload; SFU depends on server resources, throughput, stream quality, and deployment design.
Can I white-label it?
Yes. Full source code is included for branding and custom development.
